# Setowa submission checklist

Check the organizer's current portal, deadlines, repository-visibility rules, and prior-work disclosure requirements before submitting. This list is a team preparation aid, not a claim that submission is complete.

## Product and evidence

- [ ] The demo clearly labels synthetic media, or uses cleanup photos/videos with documented permission and source attribution.
- [ ] A before/after pair is from the same site and strictly ordered visits.
- [ ] A reviewer has checked the AI draft or the explicit unreliable result against the images.
- [ ] An edit resets approval; rejected and pending observations stay out of the report.
- [ ] Reload retains the approved record. Exported wording and original links match the saved review.
- [ ] Any quantity has a separately recorded measurement and source.

## Technical and presentation

- [ ] `cd backend && python -m pytest -q` passes on the release commit.
- [ ] Showcase and workspace work on the presentation laptop in light and dark themes.
- [ ] The final demo environment has keys configured privately; no secrets, tokens, or real user media are committed.
- [ ] Architecture slide matches the implemented stack; limitations and real-provider testing status are stated accurately.
- [ ] Video and deck use current Setowa branding and Team LEX credits.
- [ ] A synthetic backup demo is available if network or provider access fails.

## Submission

- [ ] Confirm the private repository is accessible to judges, or make a reviewed public release if the rules require it.
- [ ] Disclose pre-event work and reused components as the organizers require; preserve Git provenance.
- [ ] Verify all shared URLs in a browser that is not logged into the team accounts.
- [ ] Save the actual submission confirmation and final artifact links for the team.
