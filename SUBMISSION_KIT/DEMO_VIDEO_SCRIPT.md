# Setowa demo video — recording guide

Target a short, watchable walkthrough. Confirm any event-specific duration or format in the submission portal before exporting. Use real permissioned media only when the team has recorded usage rights; otherwise clearly show the synthetic sample label on screen.

| Segment | Show | Say |
| --- | --- | --- |
| Problem | Two cleanup visits and the question “what can we actually claim?” | “Photos are useful, but a public cleanup report needs dates, sources, and a human-reviewed statement.” |
| Product | Setowa showcase, then project list | “Setowa links field media to a traceable report. LEX is the team behind it.” |
| Evidence | Site, two dated visits, before/after selector | “Both images must be from the same site, and the before visit must be earlier.” |
| Comparison | AI draft or explicit unreliable result | “The model can suggest visible change, or say the pair is insufficient. It cannot infer kilograms from photos.” |
| Human review | Edit/approve or reject, then reload | “A person approves the exact words. Editing evidence or text sends the observation back for review.” |
| Report | Export Markdown and point to sources | “The report uses saved approved records and original links; sourced measurements are separate.” |
| Close | Architecture slide and limits | “FastAPI, SQLite, Cloudinary, and optional Gemini support the workflow. Real-pair validation and public deployment are the next steps.” |

Record a backup synthetic walkthrough in case a provider is unavailable. Do not describe the sample as real field evidence or imply a live Gemini call if one did not occur. Hide credentials, reviewer tokens, private media, and browser notifications in the recording.
